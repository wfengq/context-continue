# 核心库：长项目模式（只追加的每 Bot 简报流）

- 日期：2026-11-06
- 状态：待实现
- 上游：`2026-11-05-stream-brief-estimate.md`（原型与估算）、`2026-10-11-group-context-layer-design.md`（第 5、6 节）

## 1. 背景与决定

估算结论（公平核算，含 Bot 自身输出）：只追加的简报流在超长项目上费用约为 D/E 的 1/4、单次上下文约 1/10，可见率 93–96%；长项目与 D/E 持平；短项目贵约 50%。

决定（2026-11-06，按负责人判断执行）：
1. 把简报流做进核心库，定位为**长项目模式**：可选开启，或按项目历史长度自动开启；短项目沿用现有简报。
2. **撤下的契约保留可见**：重新拆分撤下的契约进入项目板的"已撤下契约"记录，长项目模式的快照与追加中带上它们（紧凑形式，含规格原文）。理由：剧本的事实定义与 D/E 的行为都认为它们仍需被知道；工作块结束后，后续工作仍依赖当时的接口约定。
3. 用真模型衡量质量放到下一阶段。

## 2. 核心库

### 2.1 选项

- `createProject({ …, stream?: { mode?: 'off' | 'on' | 'auto'; restreamTokens?: number; autoAfterEntries?: number } })`
  - 缺省 `mode: 'off'`：所有现有行为与输出逐字节不变。
  - `on`：所有 Bot 使用流。
  - `auto`：账本条目数达到 `autoAfterEntries` 后对之后的请求使用流（缺省值由第 3 节的评测决定，写入文档）。
  - `restreamTokens` 缺省 8,000。

### 2.2 接口

- `project.buildStream(botId, { maxTokens, trigger, request?: { kind: 'brief' } | { kind: 'review'; deliverableId } | { kind: 'planning' } })` → `ContextBundle`：返回该 Bot 本次请求的完整段列表（前缀 + 本次追加，或新快照），所有段标记可缓存；`stats` 覆盖全部段。行为与现有方法一致：叫醒、已看过确认、审查与拆分上下文的状态变化不变。
- `project.recordOwnOutput(botId, text)`：宿主把该 Bot 本次的回复与工具调用文字交给核心库，追加到流里（计入重新快照预算）。不调用时流里不含 Bot 自身输出。
- 关闭时这两个方法仍可调用：`buildStream` 退化为现有的 `buildBrief` / 审查 / 拆分上下文，`recordOwnOutput` 不做任何事。

### 2.3 流的内容（结构化，不解析文字）

- **快照：** 公共说明、记忆、工作区、项目板（含全项目信息全文与"已撤下契约"）、投影；以及截至快照的全部人类消息——人类消息超过 `snapshotHumanKeep`（缺省 40）条时，更早的折叠为一段"较早的指示"摘要行列表（每条只保留前 160 个字符）。
- **追加：** ①全项目信息变更：按 id + 版本的项目板变更事件（新增、改版、撤下——撤下的契约以紧凑形式进入"已撤下契约"并追加一次）与新的人类消息；②该 Bot 的记忆、笔记、投影的条目级变化（新增、内容变化、删除；已读压缩不算变化），按小节与工作块归组；③核心库增量中与该 Bot 相关的条目（去掉已作为全项目信息追加的人类消息）；④触发说明；⑤`recordOwnOutput` 的文字。
- **重新快照：** 快照后追加超过 `restreamTokens` 时，下一次请求发新快照。
- 流状态（已显示的条目与版本、人类消息序号、各小节条目、上次的段列表）按 Bot 持久化在存储中；内存与 SQLite 两种存储行为一致。

### 2.4 项目板

- `ProjectBoard.retiredContracts?: Contract[]`：批准的新计划不再包含某契约时，该契约（最后版本）进入此列表；读取旧数据时缺省为空。现有简报与公共项目板渲染不显示它（关闭流时输出不变）。

## 3. 评测

- C 组新增 `--c-stream core`：使用核心库的 `buildStream` 与 `recordOwnOutput`（宿主按 E 的作者格式提供自身输出）；保留原型 `on` 以便对照。
- 核对：`core` 与原型 `on` + 自身输出在同一预算下费用与可见率接近（差异原因写明）；其他组不变；输出确定。
- 选择 `autoAfterEntries`：在三档剧本上运行 `auto` 的若干阈值，取"短剧本不开启、长与超长剧本开启"的阈值，写入文档与 README。

## 4. 不做

- 真模型评测。
- 改变叫醒规则。
- 让宿主改用流以外的方式记录自身输出。
