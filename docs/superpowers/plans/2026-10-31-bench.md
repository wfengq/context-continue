# 评测 `@context-continue/bench` 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用脚本化假模型，在三个剧本上比较 A–F 六组上下文策略的输入 token、可缓存部分、请求次数和上下文长度，输出可复现的 JSON 和 Markdown 报告。

**Architecture:** 一个运行器按剧本步骤逐步推进；每组策略决定"叫醒谁、请求里放什么"，通过运行器的 `call()` 发出请求；运行器统一计数、记录、调用假模型。C 组直接调用核心库的公开 API；B（Grok Bot 式）和 F（Dots + Space 式）按公开描述近似；其他组在本包内实现各自的历史/增量规则。指标与报告只读取调用记录，输出确定。

**Tech Stack:** Node.js 22、TypeScript 6.0.3、pnpm workspace、vitest 5.0.4、zod 4.6.7；依赖 `@context-continue/core`（workspace）。

**Spec:** `docs/superpowers/specs/2026-10-31-bench-design.md`（执行者必须同时阅读；本计划只写节号）。

## Global Constraints

- 包名 `@context-continue/bench`，`"type": "module"`，`strict`；版本固定 `typescript@6.0.3`、`vitest@5.0.4`、`zod@4.6.7`、`@types/node@^22`；依赖 `"@context-continue/core": "workspace:*"`。
- 测试与类型检查直接使用核心库源码：`packages/bench/tsconfig.json` 的 `paths` 与 `vitest.config.ts` 的 `resolve.alias` 都把 `@context-continue/core` 指向 `../core/src/index.ts`；vitest worker 同样加 `--no-warnings=ExperimentalWarning`。
- 不发起任何网络或模型调用；token 一律用核心库 `defaultCountTokens`。
- 所有组使用同一段固定说明模板 `BASE_TEMPLATE`（英文常量，见 Task 2）。
- 默认参数（spec §5–6）：`idleReply = "Noted."`；E 组窗口 `128000`、压缩比例 `0.8`、摘要 `1500` token、首次可见 `12` 条、之后最多 `24` 条、群组记忆上限 `8000` 字符、调用上限 = 成员数 × `3`；费用比例：可缓存 × `0.1` + 其余 × `1`。
- 输出确定：除结果目录名中的时间戳外，同一输入两次运行逐字节相同（不遍历无序结构；数字格式固定；不读取时间）。
- 命令：`pnpm -C packages/bench test`、`pnpm -C packages/bench typecheck`；每个任务结束两者都必须通过且输出无警告。

**本计划对设计文档的补充：**
- **合并规则的判定**（spec §4）：在第 i 步叫醒 Bot X 时，若第 i+1 步是以 X 为执行者的剧本步骤（`work` 的 `botId`，或 `review`/`replan` 的负责人），则不计额外请求。
- **执行者**：`work` 为其 `botId`；`review`、`replan` 为 `scenario.lead`；A 组所有剧本步骤的执行者都是唯一的 `solo`。
- **历史型组（A/B/D/E）的消息文本格式**：人类消息 `[human <id>] <text>`；Bot 回复 `[bot <id>] <reply>`；工具结果 `[tool <botId>] <name>: ok`（这些组不校验工具参数）；交付物在 D 组中以 `[deliverable <workstreamId> v<n> ref]` 代替全文，其他历史型组以 `[deliverable <workstreamId> v<n>] <content>` 全文出现。
- **E 组群组记忆内容**：成员第一次被叫醒时，用"目标 + 约束 + 截至当时出现的约定"生成文本并截到 8000 字符，此后该成员会话内冻结。
- **E 组的 Bot @ 唤醒**：Bot 回复文本中出现 `@<成员 id>` 即视为提及。
- **C 组的初始唤醒**：`approvePlan` 返回的唤醒同样按合并规则计入额外请求（这是项目板方案的真实成本）。
- **C 组 `review` 步骤**：`deliverableOf` 是工作块 id，取该工作块最新交付物的 id 调用 `submitReview`。
- **结果目录**：`<out>/<stamp>/`，`stamp` 默认为 UTC 时间 `YYYYMMDDTHHmmssZ`，可用 `--stamp` 指定（测试用）。

## Review Focus

1. **重新拆分后引用已删除的工作块**：`replan` 之后的 `work` 步骤若引用了被拆分移除的 `workstreamId`，加载时报错并指出步骤序号，而不是运行到一半失败。→ Task 1 测试。
2. **@ 了不存在的成员**：`human.mentions` 中的 id 不是员工时，加载时报错。→ Task 1 测试。
3. **某个 Bot 一次都没被叫醒或剧本没有人类消息**：指标中位数/P90 对空集合返回 0，节省百分比在分母为 0 时输出 `n/a`，不得出现 `NaN` 或 `Infinity`。→ Task 8 测试。
4. **C 组工具参数不合法**：核心库抛出的错误记录为该 Bot 的工具结果并计数，运行继续，报告列出错误次数。→ Task 7 测试。
5. **E 组调用上限暂停后人发言**：暂停期间 Bot 的 @ 不叫醒任何人；下一条人类消息恢复计数。→ Task 5 测试。

### Task 2: 假模型、运行器与 A 组（单 Agent）

**Files:**
- Create: `src/model.ts`、`src/runner.ts`、`src/text.ts`、`src/policies/single.ts`、`src/policies/index.ts`
- Test: `test/runner.test.ts`、`test/policy-single.test.ts`

**Interfaces:**
- Consumes: Task 1 类型。
- Produces：
  - `interface ModelRequest { botId: string; segments: { text: string; cacheable: boolean }[]; scripted: { reply: string; ops: ToolCall[] } | null }`
  - `interface Model { complete(r: ModelRequest): Promise<{ reply: string; ops: ToolCall[] }> }`
  - `class ScriptedModel implements Model { constructor(idleReply: string) }`：`scripted` 非空时原样返回，否则返回 `{ reply: idleReply, ops: [] }`
  - `const BASE_TEMPLATE: string`：固定英文说明（"You are a member of a project team … reply concisely …"），所有组的首段
  - `interface RunContext { scenario: Scenario; count(text: string): number; call(a: { botId: string; step: number; kind: 'scripted' | 'extra'; segments: { text: string; cacheable: boolean; kind?: string }[] }): Promise<{ reply: string; ops: ToolCall[] }>; isMerged(botId: string, step: number): boolean; actorOf(step: Step): string }`
    - `call` 计 token、写入一条 `CallRecord`（`cacheableTokens` 为可缓存段之和；有 `kind` 的段写入 `segments`）、调用模型；`kind: 'scripted'` 时把该步骤的 `reply/ops` 作为 `scripted` 传给模型
    - `isMerged`：本计划补充中的合并规则
  - `interface Policy { group: Group; onStep(step: Step, index: number, ctx: RunContext): Promise<void>; finish(): Promise<PolicyStats> }`
  - `runScenario(s: Scenario, policy: Policy, opts?: { model?: Model }): Promise<{ records: CallRecord[]; stats: PolicyStats }>`
  - `createPolicy(group: Group, opts: PolicyOptions): Policy`，`PolicyOptions { window: number; compactRatio: number; summaryTokens: number }`（本任务只接 A，其余组在各自任务中加入）
  - `text.ts`：`fmtHuman(id, text)`、`fmtBot(id, reply)`、`fmtTool(botId, name)`、`fmtDeliverable(wsId, version, content | null)`，格式见本计划补充
